# Данные и обработка событий

Для прогноза нужны зарегистрированный канал, его паспорт и история событий. Принадлежность канала объекту должна быть известна заранее.

Журнал CSV использует следующие поля:

| Поле | Что содержит |
| --- | --- |
| `ид_события` | Номер записи журнала. |
| `ид_канала_данных` | Номер зарегистрированного канала. |
| `дата`, `время` | Момент регистрации события. При импорте поля объединяются. |
| `тревожное` | Исходный признак тревоги. |
| `значение_датчика` | Число или текстовое состояние. |

Числовые показания сохраняются как числа. Текст остаётся в исходных данных `raw`, а поле `value` получает `null`. Например, текстовое состояние не заменяется нулём только для того, чтобы передать его в расчёт.

Здесь описан импорт русскоязычного журнала CSV.

### Порядок расчёта по каналу

1. Аналитик сохраняет паспорт канала.
2. В приложение загружается история событий.
3. Диспетчер или аналитик выбирает канал и время расчёта `as_of`.
4. Программа использует события до этого времени и готовит 19 признаков.
5. CatBoost рассчитывает исходную вероятность, затем применяется калибровка.
6. Прогноз сохраняется вместе с каналом, объектом, горизонтом и версией модели.
7. Диспетчер открывает результат и записывает решение.

Часовые и календарные признаки рассчитываются по `Europe/Moscow`. Если во времени не указана зона, используется московское время.

Если в текущем часе уже есть тревога или нет ни одного события, прогноз новой тревоги не рассчитывается.

### Прогнозы по правилам

Правила используют показания и доступные сведения об объекте. Для пожара в спецификации рассматриваются температура и дым, для подтопления насосы, питание и погода, если она есть. При разборе сработок учитываются состояние датчиков и плановые работы.

Эти результаты показываются с источником `rules`. Они рассчитаны по правилам, без обученной модели. Сроки обслуживания в демонстрации условные.
