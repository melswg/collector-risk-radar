# Модель прогноза новой тревоги

### Что она предсказывает

Модель `incident_24h.cbm` оценивает вероятность появления новой записи `тревожное=true` на спокойном канале в следующие 24 часа.

| Параметр | Значение |
| --- | --- |
| Цель | `new_alarm_24h`. |
| Горизонт | 24 часа. |
| Метод | CatBoost с калибровкой isotonic для канала. |
| Вход | Паспорт, история канала и время `as_of`. |
| Число признаков | 19. |
| Тип события | `unknown_pending_dispatcher`. |
| Источник | `model_kind=ml`. |
| Уровень риска | `unrated`, поскольку порог действия ещё не выбран. |

Новая тревожная запись не обязательно означает аварию. Модель не выдаёт отдельные вероятности пожара, газа и подтопления. Результат должен проверить диспетчер.

### Файлы для запуска

Для расчёта используются:

* `ml-заново/feature_builder.py`;
* `ml-заново/inference.py`;
* `ml-заново/requirements-inference.txt`;
* `ml-заново/models/incident_24h.cbm`;
* `ml-заново/models/new_alarm_channel_isotonic.joblib`.

Признаки рассчитываются по часам. Для `methane_delta` используется ограничение 48 часов. История тревог 2021 года исключена, как и при обучении. Расчёт признаков описан в `ml-заново/feature_builder.py`.

### Обучение и калибровка

| Данные | Назначение |
| --- | --- |
| 2019, 2020, 2022, 2023, 2024 | Обучение. |
| 2021 | Исключён. |
| 2025 | Калибровка. |
| 2026 | Тестирование. |

Калибровка корректирует шкалу вероятности. Порог оценки объекта за день не применяется к прогнозу одного канала. По умолчанию каналовый порог не задан.

Для повторной калибровки нужны `calibrate.py`, polars и таблица `model_tables/all_years_hourly.parquet`. Таблица хранится отдельно от репозитория. Запуск:

```bash
.venv/bin/python ml-заново/calibrate.py
```

### Оценка качества

Метрики на отложенной выборке приведены в [основном README](../../README.md#качество-модели). Вероятность отдельного прогноза зависит от входных событий и времени расчёта; она не является оценкой точности модели. Качество на непрерывном рабочем потоке не измерено.

### Остальные модели

В истории проекта описаны модели `fault`, `new_incident`, `critical` и `false_alarm`. Они не подключены к текущему сценарию как дополнительные готовые прогнозы.

`critical` объединяет несколько типов опасных событий. `false_alarm` относится к уже существующей тревоге. Их нельзя переименовать в отдельные прогнозы пожара или проникновения без согласования смысла результата и проверки.
