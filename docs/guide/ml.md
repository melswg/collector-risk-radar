# Модель прогноза новой тревоги

### Что она предсказывает

Модель `incident_24h.cbm` оценивает вероятность появления новой записи `тревожное=true` на спокойном канале в следующие 24 часа.

| Параметр | Значение |
| --- | --- |
| Цель | `new_alarm_24h`. |
| Горизонт | 24 часа. |
| Метод | CatBoost с калибровкой isotonic для канала. |
| Вход | Паспорт, история канала и время `as_of`. |
| Число признаков | 19. |
| Тип события | `unknown_pending_dispatcher`. |
| Источник | `model_kind=ml`. |
| Уровень риска | `unrated`, поскольку порог действия ещё не выбран. |

Новая тревожная запись не обязательно означает аварию. Модель не выдаёт отдельные вероятности пожара, газа и подтопления. Результат должен проверить диспетчер.

Признаки рассчитываются по часам. Для `methane_delta` используется ограничение 48 часов. История тревог 2021 года исключена, как и при обучении. Полный список названий 19 признаков в использованных файлах Markdown отсутствует.

### Обучение и калибровка

| Данные | Назначение |
| --- | --- |
| 2019, 2020, 2022, 2023, 2024 | Обучение. |
| 2021 | Исключён. |
| 2025 | Калибровка. |
| 2026 | Тестирование. |

Калибровка корректирует шкалу вероятности. Старый порог, выбранный для оценки объекта за день, не применяется к новому прогнозу одного канала. Для него нужно отдельно выбрать порог на рабочих данных.

Для повторной калибровки нужны `calibrate.py`, polars и таблица `model_tables/all_years_hourly.parquet`. Часовая витрина была передана команде 29.09.2026, но хранится локально вне репозитория. Пересчёт калибровки воспроизвёл отгруженные числа; подробности — в [статусе передачи](../HANDOFF_STATUS.md). При наличии витрины команда:

```bash
.venv/bin/python ml-заново/calibrate.py
```

### Проверенный пример

Для фиксированного искусственного примера `tests/fixtures/ml_channel_example.json` в документации указан результат `0.03470437017994859` после калибровки.

При одном запуске демонстрации через API получено `0.0974822466107166`. Это значение зависит от даты и часа. Оба числа показывают результат конкретного расчёта, а не точность модели.

Численные Precision, Recall, PR-AUC и Brier в этот документ не перенесены: Markdown-файлы отсылают к отдельным файлам метрик. Качество на реальном потоке ещё предстоит проверить.

### Остальные модели

В истории проекта описаны модели `fault`, `new_incident`, `critical` и `false_alarm`. Они не подключены к текущему сценарию как дополнительные готовые прогнозы.

`critical` объединяет несколько типов опасных событий. `false_alarm` относится к уже существующей тревоге. Их нельзя переименовать в отдельные прогнозы пожара или проникновения без согласования смысла результата и проверки.
