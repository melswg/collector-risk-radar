# С чего начать · 29.09.2026

1. Прочитайте [README.md](README.md) для запуска и честных границ прототипа.
2. Сверьте актуальное состояние с [статусом передачи](docs/HANDOFF_STATUS.md) и Git: `git status -sb`, `git log -1 --oneline`, `git fetch origin` и `git log -1 --oneline origin/develop`. Исторические документы не заменяют фактический HEAD.
3. Перед изменением кода прочитайте [AGENTS.md](AGENTS.md), [COORDINATION.md](COORDINATION.md), нужный раздел [PLAN.md](PLAN.md) и [REQUIREMENTS_CHECKLIST.md](REQUIREMENTS_CHECKLIST.md). Запишите, какие файлы берёте, в командный чат сами; агент не отправляет сообщения людям без прямого поручения.

Рабочая интегрированная ветка — `develop`; UI из `ux-ui` уже в ней. `ml` содержит офлайн-модели, но онлайн-вызов из backend не готов. `main` не объявлена готовой сдачей. На момент обновления этих документов последняя проверенная версия кода `develop` — `36703d6`; следующие коммиты нужно оценивать отдельно.

## Границы проверенного

30 тестов backend и 16 тестов frontend прошли, production-сборка прошла. Локально проверены пять ролей и HTTP-путь с записью решения и комментария. SQLite audit lock и миграционный путь `schema.sql` исправлены. Это не подтверждает PostgreSQL, Redis, LDAP, 20 пользователей, внешние уведомления или реальный ML.

`/demo.html` работает без backend на локальных данных браузера. Обычная `/` использует API. На карте показана демонстрационная геометрия; камеры не передают видео. Telegram/SMS/email отображаются как настройки, серверные каналы отключены.

## Что брать следующим

- Backend: чистый стенд PostgreSQL/Redis и миграции; проверки целевой БД, прав, аудита и сохранения решений.
- ML: [стык](docs/ML_INTEGRATION_HANDOFF.md), [пример доступного запроса](contracts/ml/available_data_request.json), справочник каналов, точные признаки и запускаемый inference. Четыре выхода модели и четыре типа backend нельзя отождествить по имени.
- Frontend: [незавершённая UX-приёмка](frontend/UX_ACCEPTANCE.md) на интегрированном `develop`.
- Сдача: [открытые задачи](ЧТО_ОСТАЛОСЬ_СДЕЛАТЬ.md), повторные проверки, документация и презентация. Официальные пункты чек-листа отмечать только после полного выполнения в `develop`.

Если локальный checkout содержит чужие изменения, сохраните их и работайте в отдельном worktree. Не включайте чужие файлы в свои коммиты.
