# Collector Risk Radar

Сервис поддержки диспетчера инженерных коллекторов, задача №8 «Москоллектор».

## UX/UI: отдельная рабочая ветка `ux-ui`

На 28 сентября текущая разработка интерфейса перенесена в `ux-ui`. Это промежуточная версия светлого голубого оформления: карта с инспектором участка, ролевые рабочие места, схема для техника, перемещаемый помощник и полноэкранный критический прогноз. Визуальная доводка продолжается: на отдельных ролевых экранах ещё конфликтуют старые и новые стили. Эту фиксацию не считать финальной приёмкой дизайна.

Для проверки механики без backend: `cd frontend && npm ci && npm run dev`, затем `/demo.html`. Демонстрационные логины: `dispatcher`, `technician`, `manager`, `analyst`, `admin`; пароль для этой локальной имитации: `demo`. Решения и комментарии хранятся в браузере. Обычный `/` использует серверный API; адаптер включается только на `/demo.html`. Реальные камеры, ML и доставка Telegram/SMS/email этим режимом не проверяются.

Проверены production build, сохранение решения диспетчера, красный сигнал, схема техника и чтение его комментария руководителем. Ветка предназначена для дальнейшей проверки UX/UI перед интеграцией в `develop`; официальные требования дополнительно не отмечались выполненными.

Текущий локальный интерфейс: у диспетчера схема объектов и инцидентов над приглушённой картой Москвы, очередь прогнозов, карточка с телеметрией, проверкой доступности камеры и решением. Подложка загружается из бесплатных тайлов OpenStreetMap с атрибуцией. **Соединения на схеме, расположение узлов и координаты демонстрационные**: реальных трасс и видеопотоков нет. Официальный источник геометрии и условия карты для закрытого контура остаются открытыми. Роли разведены: технический специалист видит схему работы, советы к проверке и общие с диспетчером комментарии к рекомендациям; руководитель — приоритеты и очередь; аналитик — проверку прогнозов и решений. Помощник-крот (на выбор также бобёр и лиса) перемещается по экрану и даёт разные сведения по роли, но не управляет оборудованием. Мобильная навигация и светлая/тёмная темы сохранены; новый дизайн сначала проверяется в тёмной теме. Экран явно показывает источник правил и синтетики. Правила интерфейса: [STYLE.md](STYLE.md), происхождение изображений: [DESIGN.md](docs/DESIGN.md).

Для просмотра без входа есть локальные макеты `/map-preview.html` и `/alert-preview.html` после запуска Vite. Основная карта диспетчера теперь интерактивная и векторная (MapLibre + OpenFreeMap): её можно двигать, приближать, возвращать к центру Москвы, включать условные трассы и 18 демонстрационных камер. Камера открывает карточку участка со схематичным ракурсом и честным состоянием «видеопоток не подключён». Трассы, координаты объектов и камер вымышлены для UX-макета, не являются фактической геометрией сети. Старый режим условной схемы остаётся отдельным. Красный экран показывает риск как прогноз, не как подтверждённую аварию. Изменения этого этапа касаются только frontend.

`/map-preview.html?workspace=dispatcher` показывает настоящий компонент Dashboard на демонстрационных данных без входа. Выбор прогноза открывает карточку рядом с картой; нажатие на тоннель открывает ближайшую условную камеру. Кнопка «Вся сеть» возвращает общий вид. Подложка города, туннельный слой и маркеры перемещаются совместно; геометрия тоннелей не привязана к экранным пикселям. В простом макете на мобильном карта и список сигналов доступны отдельными вкладками. Запись решений и серверные действия в предпросмотре не выполняются.

Три канала внешних уведомлений подготовлены как отключённые по умолчанию адаптеры с явной отправкой администратором. Синтетические, повторные и неподтверждённые источники во внешнюю очередь не допускаются. Живые получатели и провайдеры ещё не настроены; подробности в [DELIVERY.md](docs/DELIVERY.md).

Новый `/api/v1/ml/native/` принимает подготовленные признаки канал-час, обращается к отдельному `ml_service /v2` и сохраняет историю с идемпотентным повтором для пользователя. Доступ ограничен admin/analyst. Старый объектный контракт остаётся legacy rules/demo: результаты ML в него не преобразуются. Генерация признаков из потока и показ в старом UI ещё не выполнены. Артефакты находятся локально в игнорируемом `data/ml-artifacts/models`, manifest: `contracts/native_ml/artifacts.json`.

Проверенные команды запуска: [NATIVE-ML.md](docs/NATIVE-ML.md). При недоступности native ML возвращаются 502/504; автоматической подмены другим rules-классификатором нет.

## Семантика моделей

- **fault**: отказ датчика в следующие 24 часа.
- **new_incident**: новый инцидент в следующие 24 часа.
- **critical**: объединённый критический инцидент (пожар, затопление или газ) в следующие 24 часа.
- **false_alarm**: оценка уже случившейся тревоги данного часа; без тревоги неприменима.

Вход модели: **канал × час**, точный набор признаков каждой головы. Старый backend-контракт fire/flood/intrusion_false_alarm/sensor_failure этим моделям не соответствует. Адаптируем сервис к ML; модели не переучиваем. Нельзя скопировать critical в отдельные вероятности пожара и подтопления.

Готовая агрегация **объект × день** использует полный день и отдельный калибратор. Это offline-результат, не прогноз, известный в начале дня. Метки ML получены из журналов и правил разметки: это proxy-метки, не независимая физическая истина.

## Запуск и проверка

После импорта develop его Makefile содержит make local, make up, make up-ml, make seed. Наличие целей не означает успешный запуск. Проверенные команды актуального подключения ML должны быть записаны в NEXT и LOG после их выполнения.

Базовые проверки при подготовленной среде из корня проекта:

```bash
python3 -m pytest -x -vv
npm --prefix frontend run build
```

Приёмка ML требует настоящего inference, HTTP-пути, сохранённого результата и проверки недоступности модели. Полная приёмка дополнительно требует браузера, чистой БД и эксплуатационных проверок.

Rules, stub, ML и offline replay должны различаться в API/UI. Пропущенные признаки не означают нулевой риск. Решение диспетчера не становится подтверждённой меткой автоматически. Внешние системы доступны только на чтение.

Локальная история начата из ZIP и не является историей GitHub. Перед публикацией переносим изменения поверх удалённой истории без force push. Safari-сессия не означает авторизацию Git CLI. Нельзя объявлять изменения отправленными до проверки.

Сдача: проверяемый прототип, репозиторий, документация и презентация. Отдельные прогнозы пожара/подтопления и физическая достоверность proxy-целей остаются явно обозначенными пробелами.
